Q: Which assertions failed on earlier runs?
A: 
- Run 1 (task-2141): locator.click: Timeout 30000ms exceeded waiting for locator('#lifecycle-pill-rising')
  Reason: Vite dev server was still compiling/starting (took 80s on Windows) when Playwright attempted to navigate and click.
- Run 2 (task-2181): innerText mismatch on tab Rising (matched 2/10)
  Reason: In the original loop, the mock only intercepted the single tab route (e.g. **/api/trends?*) while un-intercepted secondary queries (/api/trends/emerging) hit the live backend or race-loaded into the TanStack Query cache. Furthermore, clicking the pill before React hydration finished caused the active feed to remain 'all' (showing Emerging cards at top).
- Run 3 (task-2219): Tab comparisons all passed 10/10, but detail view check failed:
  Detail view failed to load for trend 7808 (text length: 10)
  Reason: Trend ID 7808 was hardcoded from Order 74 and does not exist in the active database or snapshot.
- Run 4 (task-2249): innerText mismatch on tab Rising (matched 0/10)
  Reason: React was still hydrating when #lifecycle-pill-rising was clicked on the FULL pass, leaving the filter as 'all' (displaying Emerging cards) while the SLIM pass had successfully registered the click.
- Run 5 (task-2267): Detail view failed to load for trend 7842
  Reason: Intercepting **/api/trends/7842 with raw snapshot dict failed daptTrend parsing because the snapshot feed dict lacked specific detail-view fields. Letting the local backend serve /api/trends/7842 resolved it.
- Run 6 (task-2313 & 2335): Tab Rising Card #5 MISMATCH (matched 8/10 or 9/10):
  FULL: 🔄 Last verified: 13h ago vs SLIM: 🔄 Last verified: 12h ago
  Reason: System clock rollover across an hour/minute boundary between the first pass and second pass. Relative time was dynamically computed by the browser's JavaScript.

Q: What does normalizeCardText strip?
A: In the FIRST version:
   - Stripped GROWTH Tracking started...
   - Stripped multiple consecutive whitespace (\s+ -> ' ')
   In the FINAL version:
   - Additionally stripped relative time-ago strings: \b\d+\s*(h|m|s|d)\s*ago\b -> TIME_AGO to prevent dynamic client clock rollover between sequential test passes from causing false-positive card mismatches.

Q: Was the 'old' side the saved evidence/order78/old_payloads.json snapshot or a live call to production?
A: The 'old' side was the SAVED evidence/order78/old_payloads.json snapshot file (which contained the unslimmed SELECT * Supabase payloads exported directly from the database in Order 78). It was NOT a live call to production. The 'new' side was the exact same rows passed through slimPayload(), stripping the 46 non-feed columns.

function slimPayload(rows) {
  return (rows || []).map((row) => {
    const slimmed = {};
    for (const [k, v] of Object.entries(row)) {
      if (FEED_COLS.has(k)) {
        slimmed[k] = v;
      }
    }
    return slimmed;
  });
}

function normalizeCardText(txt) {
  return (txt || "")
    .replace(/GROWTH\s+Tracking started\.\.\./g, "")
    .replace(/\s+/g, " ")
    .trim();
}

function slimPayload(rows) {
  return (rows || []).map((row) => {
    const slimmed = {};

function normalizeCardText(txt) {
  return (txt || "")
